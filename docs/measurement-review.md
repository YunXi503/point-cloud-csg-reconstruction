# 量測完成後的再次審查

日期：2026-11-05；版本：0.1.6。這是同一執行者改從量測有效性、數值風險與實作證據準則重查，沒有冒充外部盲審。

| 審查問題 | 證據與處理 |
|---|---|
| 數字是否在原方法與參數下得到？ | 241 份保護來源前後雜湊相符，24 次階段執行的 84 項輸出 SHA 全符合原參考；事前協定及工具 SHA 一併保存 |
| 記憶體讀到的是否真正 runtime？ | 起初三次 64 MiB 探針未達門檻，停止後升層查 PID，定位到 venv 啟動器；改為同 prefix／套件的直接 runtime，PID 與配置探針再通過，原低值排除 |
| 有沒有以最快一次代表成果？ | 每組三個新程序全部保留，列中位／最小／最大；未刪慢值、未推算信賴區間或加速比 |
| 是否混入編譯、函式與完整程序成本？ | C# 分類排除準備編譯；Python CLI 含啟動及I/O；規模函式另有內部計時；M計數在另一程序。工作集仍含匯入／完整CSV讀取，未宣稱為函式獨占量 |
| N 曲線是不是全系統泛化？ | 只測原 L型板 region_growing 的既有資料子集；完整CLI在5000列仍按原10000列契約拒絕 |
| 是否把停下或小殘差當成正確？ | 0.001°有未達步長門檻的100輪回傳；0.00001°達步長但半徑誤差約3.62 mm，兩者均明列 |
| 是否把退化觀察包裝成全部通過？ | 四項解析基準與32項行為診斷分開；低秩仍回傳、None拒絕及LinAlgError均保留；23項單元測試通過不代表所有無效輸入都已防護 |
| 原因是證據還是推測？ | 同fixture SHA的事後矩陣秩／條件數查核另存，不把與病態一致的現象寫成完成內部消融的因果結論 |
| 舊索引、論文或資料是否被覆蓋？ | EXPERIMENT_LOG 原 V001–V009 保留，V010追加量測紀錄；原Word／PDF／圖件及研究輸入沒有回寫 |

該版有效性判準是：來源與環境一致、原始輸出雜湊全符、程序計時／原生峰值有效、同N重複輸入與分群標籤一致、解析基準符合事前數值界線。實際24次階段、12次規模量測與32項診斷都保存，原方法與失敗／限制不改寫。

仍未測：Python內部五階段各自的獨占時間／記憶體、含編譯的完整入口延遲、程序樹總峰值、完整方法跨N／超過10000點、其他硬體及真實掃描。這些不以相加中位數、相減高水位或新增抽象數字補齊。

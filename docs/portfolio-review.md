# 從招聘閱讀與使用者角度的補全審查

審查基準：v0.1.1；日期：2026-11-05。本頁記錄目前可見的缺口，不將建議項目當作已完成能力。

## 已處理：圖與 JSON 的表示契約

首頁原先將現有輸出直接寫成二元 CSG 樹。前三例使用候選分組格式，盲孔六角座已使用巢狀二元格式；其中模型A JSON 用四項 children 與兩項 subtractors 保存候選，沒有逐個展開二元節點。已改用 CSG 推論 JSON 的措辭，並提供[表示對照](csg-representation.md)。原演算法、候選檔及 JSON 保持不變。統一四例的輸出 schema 仍是後續工程項目。

## 待補項目與優先順序

| 優先 | 項目 | 現況與缺口 | 完成方式與所需依據 |
|---|---|---|---|
| 高 | 個人分工與設計取捨 | 已有作者及 Codex 工程整理說明，但沒有集中說明作者在研究設計、實作、實驗與驗證中的分工 | 依本人確認的實際工作填寫，連結對應程式與結果；不由檔案存在推論誰獨立完成 |
| 高 | 共通方法與案例規則對照 | 架構頁已說明案例規則；模型A的 assign_semantic_roles 另要求九個平面與四個圓柱面，並配置指定軸向的語義角色 | 列出共通幾何處理、案例專屬假設、支援輸入及拒絕條件；擴充新模型須另立研究計畫 |
| 高 | 重建品質結果摘要 | 首頁集中展示來源雜湊重現，研究品質證據仍分散於既有驗證報告及論文 | 逐例核對現行論文、報告與來源版本，整理曲面殘差、尺寸誤差、拓樸／候選查驗及 CSG 對照，保留單位與限制 |
| 中 | 一個案例的完整導讀 | 已有圖庫及輸出連結；新增表示頁只示範一個候選的回查 | 補足從點雲、面、拓樸、候選到 JSON 的實際欄位、規則及來源連結，讓讀者能跟著資料走一遍 |
| 中 | 短示範 | 圖庫為靜態圖片，尚無執行過程錄影或互動檢視入口 | 用同一案例錄製真實指令、輸出及圖件對照，清楚標示預先製作的示意圖 |
| 後續實測 | 效能與擴充能力 | 目前沒有專門的分階段時間、峰值記憶體及規模測試紀錄 | 先訂量測計畫、固定硬體／環境／資料版本，再量測；不拿 CI 總時間當演算法耗時，不估填數據 |

## 驗證還可補強之處

既有 CI 的核心為來源保護、工程防護與指定四例的輸出雜湊重現。另有歷史獨立網格參考驗證報告，不能把它們與本次 CI 全數視為同一種查驗。

若後續增加格式轉接或新入口，適合加入候選 ID 存在性、BooleanType 與 JSON 群組一致性、來源面完整性及樹格式的語義檢查；檢查規則須先對照既有方法與資料契約。

新增真實掃描、未知零件、CAD 幾何核心或新的推論方法屬後續研究／功能範圍，不能以補文件宣稱完成。

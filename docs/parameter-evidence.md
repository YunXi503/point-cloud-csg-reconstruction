## 可以補上的尺度依據

| 案例（各 10000 點） | √(面積／點數)（mm） | 最近鄰距離中位數（mm） | 最近鄰距離第 95 百分位（mm） |
|---|---:|---:|---:|
| 階梯狀圓柱 | 1.9368 | 0.9007 | 1.8633 |
| L型板 | 1.1307 | 0.5350 | 1.0826 |
| 模型A | 1.9352 | 0.9106 | 1.8691 |
| 盲孔六角座 | 2.0335 | 0.9566 | 1.9552 |

這些量提供距離門檻 1.5／2.0／2.5 mm 相對於現有取樣間距的尺度背景。√(面積／點數)是面積密度描述，不是各點間距相同的保證；最近鄰統計也不是最佳分割門檻證明。原報告的 bounding_box_diagonal_mm 實際由取樣點座標範圍計算，不能稱為完整 STL 頂點包圍盒。

法向量內積 0.90／0.93／0.96 的 arccos 角度分別為 25.8419°／21.5652°／16.2602°，只說明方向容許尺度；不能推出哪個設定對未知模型最好。初始 C# 分類器有不同的有效判準，不能用這張表改寫它們的參數。

密度原報告沒有輸入 SHA；該版八個 STL／CSV 的 SHA 是對**當前保存位元**建立的綁定，不能冒充 7 月執行收據。補入的幾何檔保留原名 [Hex Base with Hole A.stl](../evidence/traceability-2026-11-05/Hex%20Base%20with%20Hole%20A.stl)，供既有盲孔密度計算追溯；它不被改名或合併為舊資產 Hex Base with Holed。

## 語言選用：已知分工與尚缺動機

| 依據 | 可支持的說法 | 不能推出的說法 |
|---|---|---|
| 正式論文表 4.1 及其後工具分工段落 | C# 用於初始特徵辨識；Python 用於方法推論、五層驗收及圖件 | 當初選用兩種語言是因哪種更快、較省記憶體或已比較其他語言 |
| 現存 Python 匯入與程式 | NumPy／pandas／SciPy 支援數值處理，Matplotlib 用於圖件 | 語言效能優勢或歷史開發者心理動機 |
| 階梯狀圓柱 C# 的「較簡單，門檻放寬」註解及有效 3.0 條件 | 有局部參數註解可追溯 | 已做門檻最佳化或跨模型比較實驗；未使用的同名欄位不是有效設定 |

論文、四例來源與指定規劃／審查目錄中尚未找回完整的語言選型及每一參數決策紀錄。因此 M3 的客觀尺度與實際分工已補，原始動機仍列缺口；查無紀錄不等於紀錄從未存在。

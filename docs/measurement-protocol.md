# 效能與幾何診斷的事前協定

日期：2026-11-05（Asia/Taipei）；來源基準：v0.1.5／2362965ca46d2c31d085a82f18ae1164ef2cf5ef。量測範圍為現有程式的時間、記憶體、規模及退化／不收斂，原方法與參數固定。本協定是公開作品的工程量測補充，不回寫正式論文，也不以舊三案例計畫覆蓋現行四案例。

## 保護條件與版本戳

- 241 份既有研究／歷史來源、四案例輸入、期望輸出、原方法參數與論文／圖件都保持原 SHA。只新增外部量測工具、解析幾何測試 fixture、結果與說明。
- 所有執行使用固定 Python 3.14.2／既有完整依賴鎖與原 C# 來源／runtime；記錄本機硬體、OS、環境與方法檔 SHA。測試前後驗證來源，任一漂移即不解讀成結果。
- 所有工作目錄為新的 runs/ 子目錄；不覆寫來源／前版結果。按群組依序執行，不平行跑受測工作。

## A：現有四案例的兩個階段

先用既有完整入口在新目錄建立轉接器與分類器並驗證四份初始 CSV／24 份核心輸出，此次準備不列入階段計時。

各案例分別量測 C# 原分類器與 Python 原推論 CLI，各三次、每次新程序與新輸出目錄；不改演算法或參數。C# 的編譯不在分類時間內；Python 包含程序啟動、匯入、CSV 讀寫及全部推論。準備程序可能已暖化檔案系統快取，不宣稱冷機測試。保留每次原始值，以最小／中位／最大值描述，不計信賴區間或效能優越性。

**預測**：原四份初始 CSV 與每次六項核心輸出應逐位元相同；耗時與記憶體可能有背景負載及快取變異。**證偽／有效性判準**：任何輸出不同、程序非零退出、計時或記憶體無有效值，該次不能列成成功量測；不調整期望 SHA 或原方法設定。

計時使用 perf_counter_ns 的父程序 wall time，範圍是建立受測程序至結束，驗證檔案不在計時內。記憶體使用 Windows GetProcessMemoryInfo 的 PeakWorkingSetSize，單位 bytes／MiB，為受測單一程序的原生峰值工作集，含 runtime／套件與讀寫資料，不是整棵程序樹、不等於私有配置總量。先用軟體 fixture 確認已結束程序的保留 handle 仍可讀取非零峰值；無法確認就停止此量測，不猜補或靜默改成輪詢近似值。[API](https://learn.microsoft.com/en-us/windows/win32/api/psapi/nf-psapi-getprocessmemoryinfo)與[欄位定義](https://learn.microsoft.com/en-us/windows/win32/api/psapi/ns-psapi-process_memory_counters)

**正式量測前的協定修訂 1**：連續三次 64 MiB 軟體探針未達記憶體判準，已停止量測層並升層檢查程序身分。發現 Popen 的虛擬環境啟動器 PID 與真正 Python runtime 的 os.getpid() 不同；原低值屬啟動器，全部排除。改以 sys._base_executable 直接啟動 CPython，並依同版 Windows venv redirector 的 __PYVENV_LAUNCHER__ 機制保留原虛擬環境。必須重新確認子程序 PID 等於 Popen PID、prefix 與全部鎖定套件一致、64 MiB 配置探針達門檻，才開始正式數據收集。這只修正量測對象，不更換方法、套件或執行緒參數。[CPython 3.14.2 啟動器來源](https://github.com/python/cpython/blob/v3.14.2/PC/venvlauncher.c)

## B：規模僅量測既有 L型板 region_growing

使用既有 L型板初始分割 CSV 的座標／法向量。預先固定抽樣 seed=42，以單一排列的前 N 個索引建立巢狀子集，再排序索引以保留來源列順序；N 固定為 1000、2500、5000、10000，各三次獨立程序。法向量正規化依原 build_outputs 的同一處理，2.0 mm／0.93 不變，不新增點、不重取樣 STL、不加雜訊或改尺度。

每次記錄來源 SHA、索引 SHA、陣列 SHA、點對數 M、連通分量數、函式時間、程序時間與原生峰值工作集。M 在計時外另用相同搜尋條件計數；避免把額外查核混入 region_growing 函式時間。函式時間只包原函式呼叫；程序時間及峰值包含載入／抽樣等工具成本。若額外 M 計數晚於函式會污染程序峰值，必須改在獨立查核程序先計數並保留此差異。

**預測**：N 與距離候選點對 M 增加時，成本可能增加，但不預設一定單調或符合哪個實測複雜度。**證偽／有效性判準**：同一 N 的輸入／索引 SHA 不同、重複執行標籤 SHA 不一致或函式失敗，須獨立列出，不以最佳一次代替。子集的密度與覆蓋會隨 N 改變，因此不能當成全系統跨點數準確率／泛化驗證。

完整方法仍固定 10000 點。另以一個 5000 列的既有資料子集，確認原 L型板 CLI 按既有列數契約拒絕；不解除 guard 以取得完整流程曲線。不量測超過現有 10000 點的範圍。

## C：解析幾何基準與退化／收斂診斷

對既有兩份擬合實作（共用階梯狀圓柱模組、L型板匯入的原擬合輔助模組）使用相同工程 fixture；解析生成的測試資料與論文 STL 案例分開，不算新增研究樣本。

- 基準：25 點 z=3 平面與 160 點半徑 10、z 範圍 −5 至 5 的完整圓柱。位置與法向量由解析式產生；檢查有限有效欄位、殘差≤1e−6 mm、法向量／軸向一致性≥1−1e−8、圓柱半徑誤差≤1e−6 mm。這些是 fixture 驗收界線，不改原程式 1.5／0.93 參數。預期兩份原函式均符合；不符即保留失敗。
- 退化診斷：空陣列、單點、兩點、共線點、重合點；以有效圓柱另分別改為零法向量、NaN 座標或 Inf 座標。每一項獨立改一種輸入條件，記錄直接擬合及原曲面選擇器回傳、拒絕、例外、警告與位置支撐秩。低位置秩不自動等同含法向量問題無唯一解，也不替原函式發明未記錄的拒絕契約。
- 收斂診斷：圓半徑 10、中心 (2,−3)、64 點；角度覆蓋固定測 360°、10°、0.001°、0.00001°，只改覆蓋角。另保存共線／重合的二維輸入。外部 trace 只讀原 nonlinear_circle 的最後 step 與 iterations，不改局部變數；沿用原迭代上限 100、步長門檻 1e−13。記錄最後步長、原步長條件是否達成、半徑／中心誤差、殘差與例外，不把「最後回合是100」單獨當成不收斂，也不把小步長當成幾何正確。

**預測**：解析基準可符合檢查；不完整支撐或非有限輸入可能拒絕、拋例外或回傳未具防禦診斷的結果；短弧可能出現病態或未達步長門檻。這些是可被結果推翻的假設，不是先填好的結果。若未觀察到迭代耗盡，明列該分支未覆蓋，不改原上限或尋找有利設定冒充已覆蓋。

## 操作與交付

每個量測程序設 120 秒上限，幾何診斷每項 30 秒；逾時只終止本次擁有的程序並保留紀錄。非預期的同判準三連敗就停止該組、先查量測層，不對研究碼疊補丁。預期的無效輸入例外屬診斷結果，不當成改善方法的理由。

完成後原始 JSON／CSV、版本與來源綁定、測試、限制及換角度審查一起發布。未量測的內部 Python 子階段、完整流程跨 N、其他硬體與真實掃描仍分別標示，不外推。

# 圓擬合外層四項收尾：事前計畫

日期：2026-11-06（Asia/Taipei）。基準：v0.1.7／f11d62903c9eef20776bec30b6d4eaf440d35330。範圍為來源清單格式、錯誤報告、CLI重放及文件版本一致性。

## 範圍與分段

保持241份研究／歷史來源、四案例入口及期望輸出、六份圓fixture、原量測／工具／圖件、論文位元及原停止參數。原研究方法與浮點運算不調整；不把外層接入四案例流程。依序完成下列四段，每段先以對應契約測試驗證再進下一段，沒有研究因素同時變動。

1. **來源清單錯誤路徑**：解析前確認清單為list、紀錄為含有效path／sha256的dict、路徑不重複。損壞／缺件／格式無效均為blocked_source_version，不執行原非線性求解器，不以寬泛吞例外掩蓋未知程式錯誤。
2. **報告共同欄位**：API及CLI共用基礎報告，保留schema_version=1及既有狀態／退出碼；解析失敗補齊implementation、convergence、raw_result、runtime及參數未驗證原因。新增input_csv_sha256固定存在：讀到輸入時記錄原位元SHA，未讀到為null，不捏造SHA。錯誤細節與數值支撐等依狀態附加，不要求所有診斷欄位完全相同。
3. **12項CLI重放納入CI**：新增可獨立執行的重放器，固定六份CSV×兩份實作，不改fixtures。檢查CSV／陣列／來源綁定、報告共同欄位、退出碼與狀態一致、拒絕時沒有estimate，以及parameters_verified=false。依當次數值秩與可靠步長檢查分類，保留觀察；不把本機100輪／固定4-2-6分類當跨硬體必須吻合的門檻。原兩項良態fixture仍按既有1e−6解析測試判準查驗。重放失敗則CI失敗，保留報告與日誌，不藉調方法修通過。
4. **文件版本同步**：明確區分v0.1.6的23項、v0.1.7的51項與本版實測數量；歷史報告原樣，新結果另存2026-11-06目錄。將導讀連到現行CI重放與資料缺口，維持半徑準確度尚未驗證的邊界。

## 預測、證偽與驗收

預測：隔離損壞清單的TypeError會改為結構化拒絕；同為invalid_input的CLI路徑有完整共同欄位。固定六份fixture在相同本機環境應保留原4項步長達標、2項上限未達標、6項支撐不足，但只記實測，不強迫結果。合法原求解回傳應與v0.1.7相同。

證偽條件：損壞清單仍漏出預期外例外或啟動求解器、來源SHA被改寫放行、讀不到輸入卻填SHA、缺觀察／未達門檻仍有estimate、宣告半徑已驗證、任一原來源或期望輸出改變。出現時只修工程層，保留失敗紀錄；同一判準三次未解則停止補丁、升層診斷。

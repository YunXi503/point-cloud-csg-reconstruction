# 軟體／演算法面試官閱讀與審查

回答「為何選這四個模型」或「約0.03 mm殘差能說明什麼」時，可查[案例目的對照](case-validation-map.md)與[殘差證據邊界](residuals-and-stl.md)，避免將案例描述或可能歸因說成泛化／因果結論。

[首頁](../README.md) · [L型板逐層導讀](case-walkthrough.md) · [來源與數值](../provenance/interview-evidence.json) · [仍缺資料](missing-information.md)

研究內容可先讀[問題與貢獻總覽](research-overview.md)，再沿[孔洞端部判別](hole-end-conditions.md)與[拓樸規則例解](topology-rules.md)查實際面組、來源與判斷限制。這三頁整理既有論文／程式，沒有新增研究實驗。

日期：2026-11-05；版本：0.1.6。此處是依現存論文、程式、結果與測試所做的工程審查，不是實際面試評分。審查判斷為：目前能展示指定案例的幾何計算、圖關係推論、追溯與重現；未知模型泛化、規模效能及完整數值邊界仍缺直接驗證。

## 建議的程式閱讀順序

| 要確認的能力 | 閱讀入口 | 可當場檢查的內容 |
|---|---|---|
| 把研究問題轉成資料流 | [L型板導讀](case-walkthrough.md) | 點陣列→連通分量→曲面→拓樸→候選→CSG；LB_D01 可回查到面 0、2、9 |
| 實作數學及資料結構 | [region_growing](../research/tools/infer_lbracket_chapter3_method.py#L52)、[擬合輔助程式](../research/tools/correct_stepped_cylinder_nls_v2.py#L46) | KD-tree 鄰近點對、稀疏圖、SVD、投影圓最小平方法、合併集合與圖走訪 |
| 知道方法依賴的條件 | [案例範圍](method-scope.md)與[公式對照](method-traceability.md) | 固定面數、軸向、角色及門檻；不同 C# 判準與兩種 CSG JSON 格式 |
| 能處理來源漂移與失敗 | [測試](../tests/test_tool_guards.py)、[來源預檢](../tools/inference_sources.py) | 原始碼／資料漂移、覆寫、未知封裝檔、輔助程式遺失或改動會被攔下 |
| 能分清自己的工作與工具協助 | [作者分工](contributions.md) | 原研究實作由作者完成；公開轉接、鎖定環境、測試與 CI 是 2026-11-05 Codex 協助的工程整理 |

可用的簡短介紹是：「我以點位置與曲面法向量建立平面／圓柱特徵，再以拓樸與案例規則推論候選幾何單元及 CSG 結構。四個 STL 取樣案例有幾何品質與來源證據；我可以用一個候選 ID 逐層說明輸入、演算法、尺寸與布林角色。現階段尚未驗證真實掃描或任意新零件。」這是依現有證據整理的說法，沒有代填效能成果或歷史動機。

## 成本分析：從程式讀出什麼

以下是靜態分析；本輪新增的[實測報告](measurements.md)與[數值診斷](geometry-diagnostics.md)分別列出，不把靜態上界當實測曲線。N 為點數，M 為距離範圍內的候選點對數，K 為初始分量數，F 為面數，R 為未歸屬點數，m 為單次擬合點數，C 為候選單元數。已有四例兩階段時間／峰值工作集與一項函式的N曲線；尚無全方法跨N或相同工作量的比較基準，因此沒有加速比。

| 實作位置 | 可推導的成本或儲存量 | 面試時應交代的限制 |
|---|---|---|
| [L型板 C# 初始分類](../research/%E7%A2%A9%E5%A3%AB%E8%AB%96%E6%96%87/%E7%A8%8B%E5%BC%8F%E7%A2%BC%E5%82%99%E4%BB%BD/%E7%89%B9%E5%BE%B5%E8%BE%A8%E8%AD%98%E6%A0%B8%E5%BF%83%E6%BC%94%E7%AE%97%E6%B3%95/L_Bracket%E5%B9%BE%E4%BD%95%E9%82%8F%E8%BC%AF/L-Bracket%20%E5%B9%BE%E4%BD%95%E9%82%8F%E8%BC%AF.cs#L431) | 每次從 stack 取點後掃描整個 points；此分群迴圈為 O(N²) 掃描量，已標記點仍會進入 foreach 再跳過 | 這是此來源的迴圈分析，不等於所有案例分類器都相同；本輪沒有改寫或量測它 |
| Python region_growing | 先實體化 M 個點對，再作 M 次方向條件與稀疏圖建構；陣列／圖的儲存量為 O(N+M)；M 最多可達 N(N−1)/2 | KD-tree 不會消除回傳大量點對的成本。建樹、半徑搜尋與 connected_components 的實際成本另計，不能把整個方法稱為 O(N log N) |
| fit_plane／fit_cylinder | 使用 m×3 的 SVD／最小平方法資料；圓擬合最多 100 輪，每輪建立 O(m) 的殘差與 Jacobian | 輪數上限與步長門檻不等於所有輸入均收斂；已實測退化／短弧；發現100輪仍未達步長及小殘差卻有半徑誤差，見幾何診斷 |
| merge_surface_components | 以每個分量重新掃描標籤建立索引，這部分為 O(NK)；有效分量的比較有 O(K²) 個面組 | parent 字典有路徑壓縮，但未據此宣稱整體近線性。未歸屬點迴圈還會重算各面支撐範圍，其成本不能只寫 O(RF) |
| build_topology 與邊界統計 | 拓樸比較 F(F−1)/2 個面對；本例 F=12，即靜態推得 66 個面對，最後接受 24 條邊；每個面對內仍有點集搜尋 | 邊界統計另有有序面對查詢，部分 cKDTree 反覆建立。66 是迴圈面對數，並非時間量測或所有內部查詢總數 |
| graph_connected／build_candidates | 鄰接表、set、deque 查連通；建圖先掃描拓樸邊，鄰居另有排序。部分面 ID 查詢仍用 next 線性搜尋 | 不能只看到 BFS 就把整段候選推論寫成 O(V+E)，也不能把已知角色表當任意零件的通用搜尋 |
| canonical_csg_tree | 兩組候選排序 O(C log C)，組成清單 O(C) | 僅為符號表示及序列化成本，沒有包含實體幾何布林運算 |

## 測試證據與空白

| 層級 | 已有證據 | 沒有因此得到的證據 |
|---|---|---|
| 工程防護 | 17 項 unittest，使用隔離的軟體 fixture；包含 v0.1.5 新增的六項依賴預檢測試 | 幾何演算法數學正確性、數值誤差全範圍覆蓋或研究樣本增加 |
| 固定案例回歸 | 四份初始 CSV 與 24 項 Python 核心輸出；原參考值與來源保留 | 新零件、旋轉、尺度、雜訊或任意點數均有效 |
| 研究幾何品質 | 既有曲面殘差及相對獨立 STL／網格參考的候選參數誤差 | 真實掃描準確率、效能優勢或一般化 CAD 實體輸出 |
| 歷史敏感度 | 保存變體／輸出 SHA 與[事後勘誤](sensitivity-errata.md)，含一組未完成 | 所有門檻最佳、C# 內部消融或未知資料魯棒性 |

完整路徑的初始 CSV 另記位元 SHA，資料內容比較允許表示不同但同一有限 float64 值的數字；六項核心輸出仍採嚴格 SHA。應分別閱讀報告的 initial_bytes_match、initial_comparison 與 outputs，不把每種比較都稱為同一契約。

## 本輪實際改善與下一步缺口

發現的工程缺口是：CSV 入口只預檢主程式及共用階梯狀圓柱來源，L型板另外匯入的擬合輔助程式沒有完整預檢；點雲入口也缺少完整 Python 依賴預檢。現在依[固定依賴綁定](../provenance/inference-dependencies.json)檢查選定案例的主程式與本地輔助程式，新增預檢發現改動或遺失時，以 blocked-inference-source-version-mismatch 停止並保存原因；CSV 入口原有的共用來源檢查及其狀態仍保留。第三方套件仍依既有 requirements.lock.txt，這個預檢不代替套件驗證或程式沙箱。

| 尚缺或技術債 | 現有風險／本輪處理 | 後續觸發條件與補強方式 |
|---|---|---|
| 階段計時、峰值記憶體與規模曲線 | 已補四例分類／推論及函式N曲線；內部子階段／程序樹／完整跨N仍缺 | 需要效能主張時，由實驗紀錄區建立固定版本、資料、硬體、重複次數及判準後量測 |
| 幾何函式退化輸入及數值測試 | 新增4項解析基準與32項實際行為診斷，未改研究函式或掩蓋限制 | 擴充輸入或修改擬合前，先定義零法向量、共線／近退化、收斂與容許誤差契約，再建立獨立 fixture |
| 重複擬合邏輯、反覆建樹／支撐範圍計算 | 原研究來源維持，問題列明 | 要最佳化時先量測熱點；依研究規則一次一變數，避免把多個改動合成加速歸因 |
| 多案例角色、格式及契約分散 | 文件明列現狀，未硬合成通用 API | 新模型需求到來後先訂輸入／輸出及拒絕契約，再評估共用介面；保留舊版重現 |
| 單一入口來源檢查的範圍 | 本輪補主程式與顯式本地依賴；來源清單依本版靜態匯入審查 | 新增本地匯入時同步綁定與查核；動態匯入、依賴鎖的安全掃描及一般化 manifest schema 仍無完整證據 |
| 完整個人選型、失敗執行輸入收據 | [M1–M3](missing-information.md)保留 | 找到原紀錄才新增來源；不能用今天的分析補成當年動機 |

以上研究／數值工作由原研究方法與驗證範圍負責；入口、測試、封裝與契約工作由 tools／tests／examples 維護範圍負責。本輪沒有以提出待辦代替已完成測量，也沒有為了求職呈現降低原判準。

[v0.1.5 面試審查查核](../validation/2026-11-05/interview-review-audit.json)列出來源、依賴閉包、17 項工程測試及兩條回歸路徑的結果。不同面試職缺可從同一份證據查驗實作深度，無須將未量測能力改寫為成果。

測試數量依版本區分：v0.1.6合計23項（相對前版新增6項），量測結果見[量測審查](measurement-review.md)；v0.1.7合計51項（新增28項圓擬合外層／CLI測試）。上述數量均為當版合計，不是新增研究案例。

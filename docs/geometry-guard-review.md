# 圓擬合外層的再次審查

本頁為v0.1.7的審查紀錄；v0.1.8已補齊錯誤路徑、共同欄位、12項CLI重放CI及導讀版本同步，見[四項收尾審查](geometry-guard-hardening-review.md)。以下保留當版51項測試與原重放的歷史範圍。

基準 v0.1.6／1489fb2f3ddeeb688b0370870cb3fee1df08a330；依[事前計畫](geometry-guard-plan.md)完成實作後，分別從數值方法、API使用者及研究維護者角度重查。這是同一工作流程的第二次審查，不冒稱外部獨立審查。

## 主要判斷與證據

| 審查問題 | 實測或檢查 | 結論與處理 |
|---|---|---|
| 是否只是把短弧結果改好看？ | 原v0.1.6量測JSON及工具SHA保留，原241來源不變；0.001°原回傳值仍列raw_result | 沒有重新調參或抹去誤差；rank不足是拒絕，不是半徑恢復正確 |
| 用殘差或迭代數猜收斂？ | 缺步長、觀察例外、第100輪達標／未達標皆有受控軟體測試 | 只按可靠觀察的原步長條件分類；不將100輪一律視為未收斂 |
| 步長達標被誤當準確？ | 以錯半徑及零殘差的受控回傳測試驗證旗標 | 一律維持parameters_verified=false，不用殘差替代參數驗證 |
| 拒絕規則偷加角度參數？ | 預檢使用原初始化矩陣及lstsq(rcond=None)回報秩 | 不增角度／條件數門檻；條件數只診斷，秩契約仍限該float64運算 |
| 外層改動了原求解？ | 12份CLI重放，六次被允許的原函式回傳與直接呼叫完全相等；其餘六次未呼叫 | 保留原方法與參數；沒有將拒絕視為原方法成功求解 |
| 可否重現與追溯？ | 六份U,V CSV有來源、位元及陣列SHA，12項各有報告／狀態／退出代碼與命令 | 可重放實際狀態；不要求跨CPU固定100輪或同一誤差 |
| 會不會污染debugger或覆寫證據？ | 既有trace不覆蓋、例外後恢復trace、既有報告不覆寫均有測試 | 無可靠觀察則停止提供估計；CSV只讀一次後計算同位元SHA |

## 驗收結果

判準：無效／數值支撐不足不呼叫原非線性求解器，未達原門檻或缺觀察時estimate=null，不宣告參數已驗證，研究來源與既有期望輸出不得變動。

實測：51項單元測試通過，其中新增28項外層／CLI契約測試；12項同資料CLI重放為4項原步長達標、2項迭代上限未達標、6項支撐不足。4項達標仍是未驗證估計，這些分類不稱為12項求解成功。原四例兩條入口另重跑，推論各24／24核心SHA相符，完整入口另有4／4初始CSV相符。

可信依據：[測試紀錄](../validation/2026-11-05/geometry-guard-tests.json)、[原始重放及版本綁定](../validation/2026-11-05/geometry-guard-results.json)、[逐筆觀察](../validation/2026-11-05/geometry-guard-observations.csv)及[來源／回歸稽核](../validation/2026-11-05/geometry-guard-audit.json)。受控軟體回傳的政策測試與原函式實際重放分開保存。

## 審查後仍保留的限制

- 這是可選的二維入口，未插入原四案例流程，也不宣稱已補齊原三維曲面選擇器對NaN／Inf、共線或重合資料的一般處理。
- 不同尺度、平移、BLAS、NumPy或硬體可能改變數值秩及迭代。短弧幾何準確度沒有通用門檻／可信區間；沒有獨立參考就保持未驗證。
- 外部trace是診斷實作，已有debugger／trace即回報不可觀察；不作並行服務或新增效能主張。此輪沒有把外層成本混入v0.1.6量測。
- 對新的方法（例如置中／縮放、其他初始化或求解器），仍須另提出研究計畫並取得使用者方法授權。本輪沒有用那些方法修正半徑。

回退方式：停止使用可選API／CLI，或選v0.1.6標籤；原研究輸入、方法及四案例入口未受替換。後續若要將外層接入面型流程，須先確認三維契約與舊輸出影響，不能只把本二維規則套到所有低秩面型。
